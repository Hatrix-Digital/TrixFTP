# TrixFTP — Project Handoff

Date: 2026-10-29 · Version shipped: **1.1.0** · Status: **released & live**

## 1. What TrixFTP is

TrixFTP is a dual-pane FTP / FTPS / SFTP desktop client for Windows, macOS and Linux,
built with Electron. Engines: [`basic-ftp`](https://github.com/patrickhildebrandt/basic-ftp)
(FTP/FTPS) and [`ssh2`](https://github.com/mscdex/ssh2) (SFTP). All application code is
original, MIT-licensed; the two libraries are MIT as well.

- Repo: https://github.com/Hatrix-Digital/TrixFTP (branch `main`)
- Website (GitHub Pages, served from `/docs`): https://Hatrix-Digital.github.io/TrixFTP/
- Custom domain (configured in `docs/CNAME`): `trixftp.hatrix.de` — **pending user DNS record**
- Releases: https://github.com/Hatrix-Digital/TrixFTP/releases

## 4. Hunting log — issues fixed along the way

1. **Renderer OOM on drag & drop**: when `startJob` became async (via `getLiveSession`),
   `queue.pump()` re-entered synchronously and looped infinitely. Fix: reserve the slot
   synchronously (`j.state = 'starting'` inside `pump()`), guard `startJob` against
   global pause / state changed while awaiting. `activeCount`/`isBusy`/`cancel`/`clear`
   count `starting` jobs as active. Regression `test/queue.test.js`.
2. **"Session disconnected" mid-transfer**: queue jobs now re-bind to any live session
   for the same host, or open a fresh one from stored credentials (auto-reconnect).
3. **Mojibake on the website**: a PowerShell `-replace` pipeline had read a UTF-8 file
   as cp1252, baking C1 characters into `docs/index.html`. Detected by scanning for
   C1 bytes; fixed by rewriting the page as pure ASCII. Rule adopted: any scripted
   edit of UTF-8 files must be byte-safe (Node) or rewrite the file wholesale.
4. **CI failures**: (a) PowerShell mangled `-c.publish=null` into a file path — use the
   `--publish never` CLI form; (b) `.deb` build requires author e-mail in package.json —
   `"author": "TrixFTP Team <trixftp@users.noreply.github.com>"`.
5. **Default Electron icon**: generated real icons via offscreen Electron canvas render
   of `build/icon.svg`; ICO = PNG-compressed entries (16..256), ICNS = icp4/icp5/icp6/
   ic07/ic08/ic09 chunks; wired into electron-builder config and `BrowserWindow.icon`.
6. **"Client is closed because ..." / "session disconnected" on parallel uploads**:
   `basic-ftp` allows exactly one task per control connection. With `maxParallel > 1`
   two queue jobs called `stat()`/`mkdirp()`/verify on the same session at the same
   time; the second task made basic-ftp close the whole client ("User launched a task
   while another one is still running"), so every further job in that batch failed with
   "Client is closed because ...". Fix: every control-connection call in `lib/ftp.js`
   (`list/stat/getwd/mkdirp/remove/rename/chmod/setTimes/execLine/createEmpty` and the
   keep-alive NOOP) now runs through a per-session promise chain (`_run()`); transfers
   keep using their own dedicated connection, so real parallelism is unchanged. Also:
   queue retries a job once on a connection-loss error, `main.js` no longer lets a
   stale engine's close handler delete a reconnected session on the same sid, and
   `createEmptyRemote` uses the engines' serialized `createEmpty()` instead of poking
   `client` directly. Regression `test/parallel.test.js`.
7. **Nested folder upload accounting**: all descendants used to bump the TOP-level
   container's `childDone`, so a root folder could show "done" while a sub-folder was
   still uploading (and the sub-folder stayed stuck at "parent"). Jobs now carry
   `parentId` and finalize bottom-up, aggregating size/bytes per level; empty folders
   finalize immediately.
8. **Parallel queue stall after a skipped job**: when a conflict policy set a job to
   `skipped`/`done`/`canceled` (very common with `resume` + existing files), `runFile`
   returned without calling `pump()`, so with `maxParallel > 1` the remaining jobs sat
   in `queued` forever. All terminal paths now go through `Queue.settle()`
   (finishChild + pump + maybeAllDone). Regression in `test/queue.test.js` (1c).

## 6. How to build / release

```bash
npm install
npm run test:engine          # engine smoke test
npm run test:queue           # queue regression
npm run test:parallel        # parallel uploads + nested folders regression
npm run test:updater         # updater logic tests
npm start                    # dev run
npm run dist                 # local electron-builder build
```

Releasing a new version: bump `version` in `package.json` (+ `package-lock.json`),
commit to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`. The
**Build & Release** workflow builds all three OSes in parallel and publishes the
GitHub Release automatically. Never push the PAT inside the remote URL to a new machine;
instead `git remote set-url origin https://github.com/Hatrix-Digital/TrixFTP.git` and
authenticate via credential manager or a fresh token.
